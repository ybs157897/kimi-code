# agent-core-v2 质量收尾实施计划

## 背景与定位

这是 `agent/v2-upgrade` 全量迁移分支的 **engine 层质量收尾**。范围严格限定在 `packages/agent-core-v2`，修复 review 发现的 H1/H2/H3 + M1-M6 + 测试债务。

**重要边界澄清**（已确认）：H2 的 media 原图问题与迁移文档 `apps/kimi-code/docs/v2-upgrade-remaining-work.md` 的 R1（本地媒体入口）重叠但代码路径不同——H2 修的是 engine 内持久化分层违规（接入 Store），R1 是 CLI/TUI 层的 video resolver + node-sdk capability。本轮只修分层违规，**不碰 R1 的 TUI/node-sdk 部分**。

docs 侧：本轮只同步进度到 `apps/kimi-code/docs/v2-upgrade-remaining-work.md`（勾掉/标注 H2 相关项），不改 `packages/agent-core-v2/docs/` 下已有的架构文档（di/service-design/errors 等都是完成态规则文档，非"待实现"）。

## 修复批次（按等级 + 依赖顺序）

### 批次 A：H1 持久化静默吞错（最高优先，最小风险）

**根因**：两个持久化关键路径用 `.catch(() => {})` 丢弃错误，服务已注入 `log`/`telemetry` 却未用。串行队列本身设计正确（`persistWriteQueue` 链防并发写），问题只在吞错。

**修复**（保留串行链，补信号）：
1. `src/agent/task/taskService.ts:960-962`（`persistLive`）：`.catch((e) => { this.log.error('task persist failed', { taskId: info.taskId, error: e }); this.telemetry.track2(...) })`。需先确认 `ManagedTask` 能拿到 `taskId`（`info` 已是 `AgentTaskInfo`，含 taskId）。
2. `src/agent/task/taskService.ts:995-997`（`appendTaskOutput`）：同理，带 `entry.taskId`。
3. `src/session/cron/sessionCronServiceImpl.ts:678-690`（`persistEnqueue`）：两个 catch 都补 log（该服务注入了 `ITelemetryService` line 95 但无 logger——需检查是否能注入 `ILogService`，或用 telemetry 的 error 通道）。

**测试**：在现有 `test/agent/task/`、`test/session/cron/` 加：注入一个 reject 的 persistence stub，断言 log 被调用、且队列继续串行（后续 write 不被前次失败阻断）。

**验证**：`pnpm --filter @moonshot-ai/agent-core-v2 test`。

### 批次 B：H3 MCP 跨 scope 深路径重构（架构正确性）

**根因**：Session-owned 类物理放在 `agent/mcp/`，Session-scope 服务深路径 import + `new` 它们。`connection-manager.ts:10` header 明示 "Constructed by SessionMcpService"。

**关键约束**（调研确认）：
- `config-schema.ts` **必须留下**（8+ 外部消费者 + barrel 导出 `src/index.ts:516`）。
- `types.ts`、`client-shared.ts`、`client-remote.ts` 被 connection-manager 和 Agent-side `tools/mcp.ts` **双方共用**——不能简单跟随任一侧。
- 数值 linter 把 `agent/mcp` 与 `session/mcp` 当同一 domain L5（`check-domain-layers.mjs:218` + `domainFromRel` 剥离 scope tier），移动是 layer-neutral，但 barrel/test 路径要更新。
- `configSection.ts` 是 side-effect 模块（`registerConfigSection` 在 import 时执行），移动后要确保 sessionMcpService 的 import 链仍触发注册。

**修复方案**（**精准部分移动**，非整体迁移）：
- **移动到 `session/mcp/`**（Session-only 消费者）：
  - `connection-manager.ts`
  - `oauth/service.ts`、`oauth/store.ts`、`oauth/callback-server.ts`、`oauth/provider.ts`（整个 `oauth/` 子树）
  - `session-config.ts`、`config-loader.ts`（session-config 专用）
  - `configSection.ts`（仅 sessionMcpService 用）
  - `client-http.ts`、`client-sse.ts`、`client-stdio.ts`（仅 connection-manager 用）
- **留在 `agent/mcp/`**：
  - `config-schema.ts`（公共类型面）
  - `types.ts`、`client-shared.ts`、`client-remote.ts`（双方共用——改为 session 侧从 `#/agent/mcp/` import，仍是同 domain L5→L5，合规）
  - `mcp.ts`、`mcpService.ts`、`mcpDiscoveryOps.ts`、`errors.ts`、`tool-naming.ts`、`output.ts`、`tools/mcp.ts`、`tools/auth.ts`（Agent-scope）

**实施**：用 `git mv` 移动文件（保历史），更新 `sessionMcpService.ts`、`sessionMcp.ts` 的 import 路径，更新 `src/index.ts` barrel，更新 test import 路径（`test/agent/mcp/connection-manager.test.ts`、`test/agent/mcp/oauth/*`、`test/agent/mcp/session-config.test.ts` 等移到 `test/session/mcp/`）。同步 `docs/wire-manifest.d.ts` 如有引用。

**测试**：现有 MCP 测试全过即证明 import 图正确；补一个断言 `sessionMcpService` 不再 import 任何 `#/agent/mcp/` 实现类（只 import 留下的公共 `types`/`config-schema`）。

**验证**：`node scripts/check-domain-layers.mjs` + `pnpm test`。

### 批次 C：H2 手写持久化接入 Store

**根因**：两个业务域绕过已有的 Store。

**C1: `src/agent/media/image-originals.ts`**（内容寻址 blob 写入）：
- 已确认 `ISessionContext` 在 MCP 调用点已注入（`mcpService.ts:101`），且 `ISessionContext.scope('media-originals')` 给出 `sessions/<ws>/<sid>/media-originals`（相对 scope，正是 `IBlobStore.put(scope, key=hash, bytes)` 要的）。
- `IBlobStore` 是 App-scope 单例，`put/get/delete/list` 直接映射内容寻址模式。
- **方案**：把 `persistOriginalImage` 改为接收 `IBlobStore` + scope（或封装成一个小服务注入到 MCP）。`AgentBlobServiceImpl` 是模板（同样 sha256 + `IBlobStore.put`）。
- **注意**：size-capped LRU sweep（`sweepCache`）Store 不原生支持——这是 best-effort 路径，sweep 可降级为 Store 的 `list` + 按 mtime 删除，或本轮先保留 best-effort 语义（失败返回 null）只把写入接入 Store。倾向后者：最小改动达成分层合规，sweep 作为 follow-up。
- 同步 `apps/kimi-code/docs/v2-upgrade-remaining-work.md` R1 的「原图进入 session media-originals」项状态（标注 engine 侧已接入 Store，TUI adapter 仍属 R1）。

**C2: `src/app/plugin/store.ts`**（`installed.json` 原子文档）：
- `InstalledFile` 文档整读整写 + JSON——正是 `IAtomicDocumentStore` 模式（JSON codec 已内置 `jsonDocumentCodec`）。
- `PluginManager` 当前只收 `kimiHomeDir: string`，无 Store 注入。需改 `PluginManager` 构造为注入 `IAtomicDocumentStore`，用 app-level scope（如 `'plugins'`）+ key `'installed'`。
- `readInstalled`/`writeInstalled` 改为走 Store：`get<InstalledFile>('plugins', 'installed')` / `set(...)`。原子写由 Store 保证（tmp+rename 在 backend）。
- `manager.ts` 三处调用点（`:64,248,383`）相应更新。
- **注意**：`PluginService`（`pluginService.ts`）是 App-scope registered service，构造 `PluginManager` 时把注入的 `IAtomicDocumentStore` 传进去。

**测试**：`test/app/plugin/` 现有测试用真 Store over in-memory（harness 已支持），应直接过；补一个断言写失败时不静默（与批次 A 呼应）。

### 批次 D：M1 error 编码契约（系统性，分域）

**根因**：一批 domain error class `extends Error` 而非 `Error2`，跨 RPC 降级成 `internal`。模板已确认（`wire/errors.ts` subclass + `registerErrorDomain` + `src/errors.ts` 三处聚合）。

**已存在 errors.ts 的域**（只需提升现有 class 到 Error2）：
- `skillCatalog`：`FrontmatterError`/`SkillParseError`/`UnsupportedSkillTypeError` → 接入已有 `SkillErrors` codes（`skill.not_found` 等已注册，但 3 个 class 没用）。
- `task`：`TaskCancelledError` → 接入 `TaskErrors`。
- `fullCompaction`：`CompactionTruncatedError` → 接入 `FullCompactionErrors`。
- `plugin`：`PluginErrors` 已存在，**15 个 raw `throw new Error`**（manager/github-resolver/store/pluginService/archive/source）提升到 `PluginErrors.codes.*`，需新增 codes（如 `plugin.invalid_root`、`plugin.github_unresolved`、`plugin.archive_download_failed`、`plugin.installed_invalid`）。

**需新建 errors.ts 的域**：
- `app/web/tools`：`HttpFetchError`（HIGH，边界）→ `WebFetchErrors`（`web_fetch.http_error` 等，带 `status` 进 details）。
- `app/telemetry`：`TransientCloudError`（HIGH，retryable）→ `TelemetryErrors`（`telemetry.cloud_transient`，`retryable: ['...']`）。
- `app/agentFileCatalog`：`AgentFileParseError` → 新 errors.ts，且把 `this.reason` 改用标准 `cause`。
- `app/hostFolderBrowser`：3 个 HostFolder error → 新 errors.ts。
- `agent/tools/os/grep`：`GrepAbortedError` → 新 errors.ts（非 retryable）。
- `tool`：`PathSecurityError`（HIGH，安全边界）——**已有自己的 `code: PathSecurityCode` 字符串联合**，需重映射到 `ErrorCode`（`path.outside_workspace` / `path.sensitive` / `path.invalid`），保 `rawPath`/`canonicalPath` 进 details。
- `session/swarm`：6+ raw throws → 新 `SwarmErrors`（`swarm.unknown_agent_type` / `swarm.not_subagent` / `swarm.not_running` 等）。
- `app/gateway`：`gatewayService.ts:37,40` raw throws → 新 `GatewayErrors`（`gateway.unknown_session` / `gateway.unknown_agent`）。

每个新 errors.ts：加 `registerErrorDomain` + subclass，在 `src/errors.ts` 加 import + re-export + spread。

**测试**：`test/app/telemetry/events.test.ts` 已强制 naming；如需，补 error code 注册的 smoke。

## PR 策略

按批次拆多个 commit（同一分支 `agent/v2-upgrade` 或新建 `agent/v2-quality-fixes`）。每个 commit 对应一个批次，便于 review 与回滚。最后按 AGENTS.md 跑 `gen-changesets` skill 生成 changeset（internal package `agent-core-v2` → minor；CLI 行为无变化除非 H2 media 影响 TUI）。
