# 统一 config 类型到 v2（根因 A），消除 ~60 个 TS4111/TS18048/TS2532

## 根因复盘（实测确认）

消费方的 TS4111/TS18048/TS2532 错误**不是因为"前向兼容包袱"**，而是因为 SDK 有**两份重复的 `KimiConfig`/`ModelAlias`/`ProviderConfig` 定义**（`types.ts` 和 `sdk-config.ts`），且都带 `[key: string]: unknown` index signature。这个 index signature 把**已声明的字段**（`providers`/`models`）也污染成"来自 index signature"，触发 `noPropertyAccessFromIndexSignature`。

关键事实（决定设计）：
- engine 的 config 是 **section-based**：每个 section（`providers`/`models`/`services`）有独立的强类型 zod schema，通过 `config.get<T>('section')` 访问。**engine 没有顶层 `KimiConfig` 强类型**——顶层确实是开放键集合（config.toml 可有任意 section：`defaultProvider`/`services`/`web`/`experts`…），这是**正确的**，不是包袱。
- 所以 `[key: string]: unknown` 在**顶层 `KimiConfig`** 上必须保留（否则 TOML 往返 `as unknown as KimiConfig` 会坏，且会错误描述数据）。
- 但 **section 类型**（`ProviderConfig`/`ModelAlias`）的 index signature 是纯冗余——它们的字段是闭合的、可枚举的，应去掉以变成强类型。

## 设计：合并双源 + section 强类型化 + 消费方对齐

### 第 1 步：确立单一类型源
让 `sdk-config.ts` 成为 config 类型的唯一源，`types.ts` 改为 re-export 它（消除双源重复）。

### 第 2 步：section 类型去掉 index signature，字段对齐 engine 命名
- `ProviderConfig`：去掉 `[key: string]: unknown`，字段对齐 engine `kosong/provider/provider.ts`（`modelSource`/`baseUrl`/`customHeaders`/`defaultModel`/`type`/`apiKey`/`oauth`/`env`/`source`）。保留 SDK 实际需要的字段。
- `ModelAlias`：去掉 index signature，字段对齐 engine `ModelBaseSchema`（`provider`/`model`/`maxContextSize`/`capabilities`/`displayName`/`protocol`/`supportEfforts`/`defaultEffort`/`offEffort` 等）。
- `KimiConfig` **顶层保留** `[key: string]: unknown`（开放 section 集合是正确的），但 `providers`/`models` 指向强类型 section。

### 第 3 步：消费方对齐（机械修复）
section 强类型化后，消费方对 `config.providers`/`model.displayName` 等已声明字段的点访问**自动合法**（不再触发 TS4111）。剩余的：
- **TS18048/TS2532（`providers` possibly undefined）**：在访问 `config.providers[x]` 前补判空（消费方逻辑上本来就该判，~15 处）。
- 个别字段名差异（如消费方读 `config.services`）用括号访问或补到 `KimiConfig` 声明里。

### 验证
每步后跑 `npx tsc --noEmit -p apps/kimi-code/tsconfig.json`，目标是根因 A 的 ~60 错误归零，且不引入新错误。最后跑 agent-core-v2(4330)/klient(185) 测试确认无回归。

## 顺带处理：B/C/D（不需定夺的执行缺口，~30 个）
- **B（6）**：`swarm.test.ts` 等引用已删的 `SlashCommandHost.session`/`requireSession` → 改写测试用 `requireSessionRuntime()`。
- **C（22）**：测试 mock 的 `SessionControlPort`/`RuntimeAuthPort` stub 少字段 → 补齐 stub（`session`/`agent`/`submitFeedback` 等）。
- **D（1）**：`run-prompt.ts` 读 `nextFireAt` → 改成 `nextRunAt`。
- **E（散落 ~21）**：逐个修（acp-adapter ModelAlias 赋值、approval `string|undefined` 判空等）。

## 目标
全树 typecheck：146 → 0（或接近 0，残留的零散项会明确列出）。

- 这只改类型 + 消费方对齐，不改 engine config 行为。
